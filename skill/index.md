# Skill 自动进化机制

> 版本: v1.0
> 最后更新: 2026-09-21
> 变更记录: 初始版本

本文件定义 skill 随业务发展的更新规则。所有 AI 在修改业务代码时**必须遵守**这些规则。

---

## 核心原则

**Skill 是代码的唯一事实来源（Single Source of Truth）。**
代码必须与 skill 保持一致，任何业务变更都应先反映在 skill 中，再体现到代码里。

---

## 场景一：新需求与现有 Skill 冲突

**触发条件**：AI 在编码前阅读了相关 skill，发现用户的实际需求与 skill 中已记录的规则不一致。

**处理流程**：

1. **暂停编码**，不要先写代码再回头补文档。
2. **告知用户**冲突点，说明：
   - 当前 skill 中记录的内容是什么
   - 用户的新需求是什么
   - 两者之间的具体矛盾
3. **等待用户确认**：由用户决定以新需求为准、还是维持原有规则。
4. **先更新 skill**：将确认后的结论写入对应的 skill 文件。
5. **再修改代码**：按照更新后的 skill 进行编码。

---

## 场景二：产生了新的业务逻辑或规则

**触发条件**：在开发过程中，用户口述、文档中、或代码逻辑中出现了 skill 尚未覆盖的业务规则。

**处理流程**：

1. **识别新知识**：判断该业务逻辑是否属于已有 skill 的范畴（ai-coding-standards / ai-code-review / 未来新增的 skill）。
2. **告知用户**：说明发现了什么新规则，建议补充到哪个 skill 文件中。
3. **等待用户确认**：由用户决定是否纳入 skill、以及内容是否准确。
4. **先更新 skill**：将确认后的业务规则写入对应的 skill 文件。
5. **再修改代码**：按照更新后的 skill 进行编码。

---

## 注意事项

- **不要默默更新 skill**：任何 skill 变更都必须经过用户确认，即使变更看起来很小。
- **不要先代码后文档**：永远保持 skill → code 的顺序，否则 skill 会逐渐落后于代码，失去参考价值。
- **变更要精准**：更新 skill 时只改动与本次需求相关的部分，不要顺手"优化"无关内容。
- **记录变更原因**：在 skill 文件中修改时，用简短注释说明为什么改（例如"2026-09 业务确认：xxx"），方便后续追溯。

---

## Skill 文件路由

当需要更新 skill 时，根据内容类型找到对应文件：

| 内容类型 | 入口文件                                                        | 说明                                 |
| -------- | --------------------------------------------------------------- | ------------------------------------ |
| 代码开发 | [ai-coding-standards/index.md](../ai-coding-standards/index.md) | 模块划分、代码规范、注释、命名规范等 |
| 代码检查 | [ai-code-review/index.md](../ai-code-review/index.md)           | 代码质量、性能优化、安全问题等       |

未来新增的 skill 也应在此表中登记。
